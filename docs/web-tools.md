# Bounded web tools

`WebFetch` takes `url`, `prompt` and an optional `offset`, as in the reference CLI. It converts the page's main content to text (scripts, styles, navigation, forms and hidden elements are dropped). Cleaned text of at most 20,000 characters is returned as-is, without a second model request. Only a longer page is sent to the session's model, which answers `prompt` against the text with an 8,192-token output limit and is asked to keep relevant URLs; the next request then carries the answer rather than the whole page. If that summary still exceeds the output limit or is empty/oversized, WebFetch degrades to the first 20,000 characters of cleaned text with `truncated: true` and a `next_offset` instead of failing the tool.

- Pages are cached for 15 minutes per URL.
- HTTP is upgraded to HTTPS; localhost, private addresses and dotless hostnames are refused. Same- and cross-host redirects are followed for up to ten hops. A redirect from a public URL to a local or private address is refused unless the original URL was itself local, so a public page cannot bounce the request onto the internal network.
- When a public page fails with a transport error, 401/403/406/429, a 5xx, or returns a large HTML shell with almost no readable text, WebFetch retries it through the Jina Reader (`https://r.jina.ai/<url>`) and marks the result with `"via": "jina_reader"`. Reader results are cached like direct pages and keep the reader's real `content-type`, so an HTML error or challenge page is still cleaned as readable text. Raw reads, local/private URLs, URLs already on `r.jina.ai`, and requests carrying custom `headers` never fall back, so authentication headers cannot leak to a third party. Unsupported binary content such as images or archives is reported as a normal error and is not sent to the reader.
- Pages longer than 20,000 cleaned characters are summarized under `prompt` with an 8,192-token output budget; shorter pages are returned directly, and a failed or truncated summary returns the first 20,000 characters with `next_offset`.
- An HTTP proxy can be configured as `web_fetch.proxy` in `config.json` (for example `http://127.0.0.1:10808`); only `http://` and `https://` proxy addresses are accepted. Without a configured proxy, the standard `HTTP_PROXY`/`HTTPS_PROXY`/`NO_PROXY` environment is used. The model's tool input cannot choose a proxy.
- Long pages are read in parts: a result with `next_offset` is continued by calling again with it as `offset`.
- A new host asks for approval unless it is on the reference CLI's list of documentation sites; `WebFetch(domain:...)` rules allow or deny hosts. `/deep-research` children may fetch any page, subject to deny rules.
- Downloads stop at 2 MiB and have a 30-second request deadline (10-second connection timeout). Text, HTML, JSON and XML are supported; HTTP failures and unsupported binary formats fail the tool.

`WebSearch` defaults to provider-hosted search. OpenAI uses the Responses API `web_search` tool; Anthropic uses the Messages API `web_search_20250305` tool. The adapter returns up to eight structured source URLs, titles and available citation snippets. It does not extract invented links from generated prose. The selected model/endpoint must support native search; failures are reported without silently switching to public search engines. Requests have a 45-second deadline and a 2 MiB response limit.

DeepSeek conversation models in automatic mode use an **independent search service**, even when chat goes through an OpenAI/Anthropic-compatible gateway. Configure its API key, endpoint and model under **System settings → Web search (联网搜索)**. Defaults are `https://api.deepseek.com/anthropic/v1` and `deepseek-flash`; both are editable. The optional `provider` field selects the native search protocol: `deepseek` (default), `openai` (`/responses` with the `web_search` tool) or `anthropic` (`/messages` with `web_search_20250305`). When it is absent, the provider is inferred from the endpoint host (`api.openai.com`, `api.anthropic.com`) and otherwise stays DeepSeek, so existing configurations keep working unchanged. No chat key or environment key is substituted when this independent key is missing. The tool tells the user where to configure it. Settings are read for each search, so saved changes apply without restarting. Explicit `deepseek_native` also uses these independent settings.

`/search-config` (also `/config search`) runs a three-step wizard: choose DeepSeek, OpenAI, Anthropic or a custom URL and protocol; enter the API key (hidden, blank keeps the saved key, `clear` removes it); then pick a provider-specific model preset or type a model ID. Quick forms set one field: `/config search provider deepseek|openai|anthropic`, `api_key`, `base_url`, `model` or `clear`, and `dcl config set search.provider` works the same way.

**Test search (测试搜索)** sends a real search using the current form values without saving them. A blank key uses the previously saved search key. The result shows source count, elapsed time and links, or an actionable error. Testing consumes search/model usage; Save applies the verified values to subsequent conversation searches.

The separate configuration is persisted as `deepseek_search` in the application's `config.json`. Normal settings reads expose only `baseUrl`, `model`, and `hasApiKey`; leaving the key blank preserves it, and explicit clearing removes it. View and Copy explicitly retrieve the saved key through `POST /api/search-settings/key` with a `Cache-Control: no-store` response. A typed replacement takes priority for these actions. Generic configuration reads redact this key and generic updates preserve it. Search requests contain only the query, not the conversation history. Their model identity, durations and reported token usage (including reported usage on a failed search response) appear in the session/turn statistics without changing the conversation's context-window calculation.

Provider settings offer `auto`, `openai_native`, `anthropic_native`, `deepseek_native`, `public`, and `disabled`. OpenAI/Anthropic overrides retain the configured gateway origin and path prefix; built-in OpenAI/Anthropic providers can use their known defaults and supported environment authentication. Automatic DeepSeek detection uses the model ID, official endpoint or built-in provider ID. Public search runs **only when explicitly selected**: DuckDuckGo HTML and Bing RSS are queried concurrently with five-second deadlines. Calling the context-free tool endpoint cannot implicitly select a provider or public search.

Live validation on the configured local gateway confirmed OpenAI Responses native search for `gpt-6.1-sol`. The gateway's DeepSeek Messages request returned client tool calls instead of server search results, which is why independent DeepSeek configuration is required. The independent service needs a user-supplied key before live verification.

Run deterministic tests with `cargo test --lib tools::web::tests`. An optional live smoke test is available with `cargo test --lib tools::web::tests::live_public_search_and_changelog -- --ignored --nocapture`; it reports search availability and changelog response size without printing page bodies.

Run native search and routing tests with `cargo test --lib search`. To explicitly run the billable native smoke test, set `WEB_SEARCH_SMOKE_BASE_URL`, `WEB_SEARCH_SMOKE_API_KEY`, `WEB_SEARCH_SMOKE_MODEL`, and `WEB_SEARCH_SMOKE_STRATEGY`, then run `cargo test --lib tools::provider_search::tests::live_native_provider_search_smoke -- --ignored --nocapture`. It prints only model/strategy, result count, usage and elapsed time.
